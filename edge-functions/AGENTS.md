# Edge function rules

- OT overlap rules (theatre busy = planned minutes + cleaning minutes; surgeon/anesthetist busy = planned minutes) live only in findClash, copied into schedule-ot and bump-ot-booking; schedule-ot re-checks after writing because there are no DB transactions.
- Pharmacy stock lives in stock_batches (qty_on_hand per batch); only receive-stock and adjust-stock change it (adjust uses a compare-and-set on qty_on_hand and logs stock_adjustments). On hand / low stock count only unexpired batches; expiry tone is red ≤30 days, amber ≤90.
- Dispensing goes only through dispense-prescription: it plans batches first-expiry-first-out (never expired) with the same logic for preview and commit, decrements stock by compare-and-set with compensating rollback (no DB transactions), and posts one charge per dispensation row (source_type dispensation).
- Ward medication schedules (med_administrations) are built only by generate-mar-schedule, which save-prescription calls over HTTP for admitted patients; it replaces only future unrecorded doses so recorded history is never lost when a prescription is re-saved.
- Purchase requests move draft → submitted → approved/rejected → received only through their four functions; receive-purchase-request claims the request with a status compare-and-set before inserting batches (receive-stock rules) and deletes them and reopens on failure, so stock is never added twice.
- Lab sample collection/rejection goes only through collect-sample and reject-sample (status compare-and-set; barcode unique per hospital by index, retried on clash); a rejected sample returns the order to collectable, so recollection needs no new order.
- Lab result flags are computed only in enter-lab-result (numeric value vs the row's range; critical from lab_tests.parameters critical_low/high, never from the client); verify-lab-result needs a lab_tech role row with can_verify_lab and sends the critical-value push to the ordering doctor.
- Department scope is resolved only by deptScope (copied into get-department-report, get-department-patients, log-record-view, get-widget-data): dept_head → their dept_head role row's department, admin → requested department; RLS gives dept_head clinical reads only via the record's doctor's department, so reports, search and policies agree.
